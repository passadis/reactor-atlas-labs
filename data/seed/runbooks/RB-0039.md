# Mitigating failed deployment rollback on Fraud

## Symptoms

- Elevated failed deployment rollback reported on `svc-fraud`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-fraud --window 30m`
   - Expected: Ranked error signatures with counts
2. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-fraud`
   - Expected: In-use versus maximum connections
3. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-fraud`
   - Expected: Open incidents on services this one needs
4. **Confirm the alert is not a monitoring artefact**
   - Command: `atlasctl metrics show svc-fraud --window 15m`
   - Expected: Error rate and p95 both elevated in the same window
5. **Identify the last change to the service**
   - Command: `atlasctl changes list svc-fraud --since 4h`
   - Expected: A change id, or an empty list if none
6. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-fraud`
   - Expected: Each dependency reports healthy or degraded

## Mitigation

1. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-fraud --to westeurope`
   - Expected: Traffic served from the secondary region
2. **Scale out the service by one step**
   - Command: `atlasctl scale svc-fraud --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes
3. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-fraud --change CHG-2026-0001`
   - Expected: Previous revision serving traffic
4. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-fraud --class low --percent 25`
   - Expected: Low-priority request volume drops
5. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-fraud --max 200`
   - Expected: Pool utilisation falls below 80 percent
6. **Disable the offending feature flag**
   - Command: `atlasctl flags disable fraud-rollout`
   - Expected: Flag reports disabled for all cohorts
7. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-fraud --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
8. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-fraud --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-fraud --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable fraud-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-risk` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
