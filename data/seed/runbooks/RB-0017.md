# Mitigating memory leak in a long-running process on Catalog

## Symptoms

- Memory leak in a long-running process reported on `svc-catalog`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-catalog`
   - Expected: Burn rate as a multiple of budget
2. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-catalog --window 30m`
   - Expected: Ranked error signatures with counts
3. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-catalog`
   - Expected: In-use versus maximum connections
4. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-catalog`
   - Expected: Open incidents on services this one needs

## Mitigation

1. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-catalog --change CHG-2026-0001`
   - Expected: Previous revision serving traffic
2. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-catalog --class low --percent 25`
   - Expected: Low-priority request volume drops
3. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-catalog --max 200`
   - Expected: Pool utilisation falls below 80 percent
4. **Disable the offending feature flag**
   - Command: `atlasctl flags disable catalog-rollout`
   - Expected: Flag reports disabled for all cohorts
5. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-catalog --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
6. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-catalog --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-catalog --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable catalog-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-commerce` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
