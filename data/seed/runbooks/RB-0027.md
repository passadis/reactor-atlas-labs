# Mitigating token validation failures on Admin Portal

## Symptoms

- Elevated token validation failures reported on `svc-admin-portal`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-admin-portal`
   - Expected: Open incidents on services this one needs
2. **Confirm the alert is not a monitoring artefact**
   - Command: `atlasctl metrics show svc-admin-portal --window 15m`
   - Expected: Error rate and p95 both elevated in the same window
3. **Identify the last change to the service**
   - Command: `atlasctl changes list svc-admin-portal --since 4h`
   - Expected: A change id, or an empty list if none
4. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-admin-portal`
   - Expected: Each dependency reports healthy or degraded
5. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-admin-portal`
   - Expected: Burn rate as a multiple of budget
6. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-admin-portal --window 30m`
   - Expected: Ranked error signatures with counts

## Mitigation

1. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-admin-portal --max 200`
   - Expected: Pool utilisation falls below 80 percent
2. **Disable the offending feature flag**
   - Command: `atlasctl flags disable admin-portal-rollout`
   - Expected: Flag reports disabled for all cohorts
3. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-admin-portal --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
4. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-admin-portal --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
5. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-admin-portal --to westeurope`
   - Expected: Traffic served from the secondary region
6. **Scale out the service by one step**
   - Command: `atlasctl scale svc-admin-portal --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-admin-portal --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable admin-portal-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-internal` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
