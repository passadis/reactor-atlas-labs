# Mitigating elevated p95 latency on Payments

## Symptoms

- Elevated elevated p95 latency reported on `svc-payments`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-payments --window 30m`
   - Expected: Ranked error signatures with counts
2. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-payments`
   - Expected: In-use versus maximum connections
3. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-payments`
   - Expected: Open incidents on services this one needs

## Mitigation

1. **Disable the offending feature flag**
   - Command: `atlasctl flags disable payments-rollout`
   - Expected: Flag reports disabled for all cohorts
2. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-payments --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
3. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-payments --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
4. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-payments --to westeurope`
   - Expected: Traffic served from the secondary region

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-payments --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable payments-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-payments` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
