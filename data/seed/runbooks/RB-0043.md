# Mitigating connection pool exhaustion on Status Page

## Symptoms

- Connection pool exhaustion reported on `svc-status-page`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Identify the last change to the service**
   - Command: `atlasctl changes list svc-status-page --since 4h`
   - Expected: A change id, or an empty list if none
2. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-status-page`
   - Expected: Each dependency reports healthy or degraded
3. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-status-page`
   - Expected: Burn rate as a multiple of budget
4. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-status-page --window 30m`
   - Expected: Ranked error signatures with counts
5. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-status-page`
   - Expected: In-use versus maximum connections
6. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-status-page`
   - Expected: Open incidents on services this one needs

## Mitigation

1. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-status-page --max 200`
   - Expected: Pool utilisation falls below 80 percent
2. **Disable the offending feature flag**
   - Command: `atlasctl flags disable status-page-rollout`
   - Expected: Flag reports disabled for all cohorts
3. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-status-page --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
4. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-status-page --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
5. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-status-page --to westeurope`
   - Expected: Traffic served from the secondary region
6. **Scale out the service by one step**
   - Command: `atlasctl scale svc-status-page --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes
7. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-status-page --change CHG-2026-0001`
   - Expected: Previous revision serving traffic

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-status-page --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable status-page-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-internal` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
