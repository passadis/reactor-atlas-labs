# Mitigating duplicate message processing on Notifications

## Symptoms

- Duplicate message processing reported on `svc-notifications`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-notifications`
   - Expected: Each dependency reports healthy or degraded
2. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-notifications`
   - Expected: Burn rate as a multiple of budget
3. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-notifications --window 30m`
   - Expected: Ranked error signatures with counts
4. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-notifications`
   - Expected: In-use versus maximum connections
5. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-notifications`
   - Expected: Open incidents on services this one needs
6. **Confirm the alert is not a monitoring artefact**
   - Command: `atlasctl metrics show svc-notifications --window 15m`
   - Expected: Error rate and p95 both elevated in the same window

## Mitigation

1. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-notifications --max 200`
   - Expected: Pool utilisation falls below 80 percent
2. **Restart the legacy sidecar**
   - Command: `atlasctl sidecar restart svc-notifications`
   - Expected: Sidecar returns to healthy
3. **Disable the offending feature flag**
   - Command: `atlasctl flags disable notifications-rollout`
   - Expected: Flag reports disabled for all cohorts
4. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-notifications --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
5. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-notifications --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
6. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-notifications --to westeurope`
   - Expected: Traffic served from the secondary region

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-notifications --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable notifications-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-messaging` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
