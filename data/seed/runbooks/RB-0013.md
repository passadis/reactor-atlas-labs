# Mitigating connection pool exhaustion on Reviews

## Symptoms

- Connection pool exhaustion reported on `svc-reviews`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-reviews`
   - Expected: Open incidents on services this one needs
2. **Confirm the alert is not a monitoring artefact**
   - Command: `atlasctl metrics show svc-reviews --window 15m`
   - Expected: Error rate and p95 both elevated in the same window
3. **Identify the last change to the service**
   - Command: `atlasctl changes list svc-reviews --since 4h`
   - Expected: A change id, or an empty list if none
4. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-reviews`
   - Expected: Each dependency reports healthy or degraded

## Mitigation

1. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-reviews --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
2. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-reviews --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
3. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-reviews --to westeurope`
   - Expected: Traffic served from the secondary region
4. **Scale out the service by one step**
   - Command: `atlasctl scale svc-reviews --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes
5. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-reviews --change CHG-2026-0001`
   - Expected: Previous revision serving traffic
6. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-reviews --class low --percent 25`
   - Expected: Low-priority request volume drops
7. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-reviews --max 200`
   - Expected: Pool utilisation falls below 80 percent

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-reviews --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable reviews-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-growth` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
