# Mitigating elevated p95 latency on Orders

## Symptoms

- Elevated p95 latency reported on `svc-orders`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Identify the last change to the service**
   - Command: `atlasctl changes list svc-orders --since 4h`
   - Expected: A change id, or an empty list if none
2. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-orders`
   - Expected: Each dependency reports healthy or degraded
3. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-orders`
   - Expected: Burn rate as a multiple of budget
4. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-orders --window 30m`
   - Expected: Ranked error signatures with counts
5. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-orders`
   - Expected: In-use versus maximum connections
6. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-orders`
   - Expected: Open incidents on services this one needs

## Mitigation

1. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-orders --to westeurope`
   - Expected: Traffic served from the secondary region
2. **Restart the legacy sidecar**
   - Command: `atlasctl sidecar restart svc-orders`
   - Expected: Sidecar returns to healthy
3. **Scale out the service by one step**
   - Command: `atlasctl scale svc-orders --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes
4. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-orders --change CHG-2026-0001`
   - Expected: Previous revision serving traffic
5. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-orders --class low --percent 25`
   - Expected: Low-priority request volume drops

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-orders --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable orders-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-commerce` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
