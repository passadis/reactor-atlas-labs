# Mitigating misconfigured feature flag on Analytics

## Symptoms

- Elevated misconfigured feature flag reported on `svc-analytics`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-analytics`
   - Expected: Burn rate as a multiple of budget
2. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-analytics --window 30m`
   - Expected: Ranked error signatures with counts
3. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-analytics`
   - Expected: In-use versus maximum connections
4. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-analytics`
   - Expected: Open incidents on services this one needs
5. **Confirm the alert is not a monitoring artefact**
   - Command: `atlasctl metrics show svc-analytics --window 15m`
   - Expected: Error rate and p95 both elevated in the same window
6. **Identify the last change to the service**
   - Command: `atlasctl changes list svc-analytics --since 4h`
   - Expected: A change id, or an empty list if none

## Mitigation

1. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-analytics --max 200`
   - Expected: Pool utilisation falls below 80 percent
2. **Disable the offending feature flag**
   - Command: `atlasctl flags disable analytics-rollout`
   - Expected: Flag reports disabled for all cohorts
3. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-analytics --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
4. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-analytics --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
5. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-analytics --to westeurope`
   - Expected: Traffic served from the secondary region
6. **Scale out the service by one step**
   - Command: `atlasctl scale svc-analytics --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes
7. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-analytics --change CHG-2026-0001`
   - Expected: Previous revision serving traffic
8. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-analytics --class low --percent 25`
   - Expected: Low-priority request volume drops

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-analytics --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable analytics-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-data` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
