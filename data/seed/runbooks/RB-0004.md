# Mitigating slow database query regression on Search

## Symptoms

- Slow database query regression reported on `svc-search`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-search --window 30m`
   - Expected: Ranked error signatures with counts
2. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-search`
   - Expected: In-use versus maximum connections
3. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-search`
   - Expected: Open incidents on services this one needs

## Mitigation

1. **Disable the offending feature flag**
   - Command: `atlasctl flags disable search-rollout`
   - Expected: Flag reports disabled for all cohorts
2. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-search --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
3. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-search --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
4. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-search --to westeurope`
   - Expected: Traffic served from the secondary region
5. **Scale out the service by one step**
   - Command: `atlasctl scale svc-search --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes
6. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-search --change CHG-2026-0001`
   - Expected: Previous revision serving traffic
7. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-search --class low --percent 25`
   - Expected: Low-priority request volume drops
8. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-search --max 200`
   - Expected: Pool utilisation falls below 80 percent

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-search --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable search-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-discovery` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
