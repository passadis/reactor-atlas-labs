# Mitigating slow database query regression on Cart

## Symptoms

- Elevated slow database query regression reported on `svc-cart`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Confirm the alert is not a monitoring artefact**
   - Command: `atlasctl metrics show svc-cart --window 15m`
   - Expected: Error rate and p95 both elevated in the same window
2. **Identify the last change to the service**
   - Command: `atlasctl changes list svc-cart --since 4h`
   - Expected: A change id, or an empty list if none
3. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-cart`
   - Expected: Each dependency reports healthy or degraded
4. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-cart`
   - Expected: Burn rate as a multiple of budget

## Mitigation

1. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-cart --change CHG-2026-0001`
   - Expected: Previous revision serving traffic
2. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-cart --class low --percent 25`
   - Expected: Low-priority request volume drops
3. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-cart --max 200`
   - Expected: Pool utilisation falls below 80 percent
4. **Disable the offending feature flag**
   - Command: `atlasctl flags disable cart-rollout`
   - Expected: Flag reports disabled for all cohorts
5. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-cart --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
6. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-cart --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
7. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-cart --to westeurope`
   - Expected: Traffic served from the secondary region
8. **Scale out the service by one step**
   - Command: `atlasctl scale svc-cart --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-cart --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable cart-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-commerce` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
