# Mitigating memory leak in a long-running process on Loyalty

## Symptoms

- Elevated memory leak in a long-running process reported on `svc-loyalty`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-loyalty`
   - Expected: In-use versus maximum connections
2. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-loyalty`
   - Expected: Open incidents on services this one needs
3. **Confirm the alert is not a monitoring artefact**
   - Command: `atlasctl metrics show svc-loyalty --window 15m`
   - Expected: Error rate and p95 both elevated in the same window
4. **Identify the last change to the service**
   - Command: `atlasctl changes list svc-loyalty --since 4h`
   - Expected: A change id, or an empty list if none
5. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-loyalty`
   - Expected: Each dependency reports healthy or degraded
6. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-loyalty`
   - Expected: Burn rate as a multiple of budget

## Mitigation

1. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-loyalty --to westeurope`
   - Expected: Traffic served from the secondary region
2. **Scale out the service by one step**
   - Command: `atlasctl scale svc-loyalty --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes
3. **Roll back the most recent change**
   - Command: `atlasctl rollback svc-loyalty --change CHG-2026-0001`
   - Expected: Previous revision serving traffic
4. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-loyalty --class low --percent 25`
   - Expected: Low-priority request volume drops
5. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-loyalty --max 200`
   - Expected: Pool utilisation falls below 80 percent
6. **Disable the offending feature flag**
   - Command: `atlasctl flags disable loyalty-rollout`
   - Expected: Flag reports disabled for all cohorts

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-loyalty --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable loyalty-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-growth` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
