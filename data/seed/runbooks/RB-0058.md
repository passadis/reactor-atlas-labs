# Mitigating connection pool exhaustion on Shipping

## Symptoms

- Elevated connection pool exhaustion reported on `svc-shipping`.
- Alert fired from the service SLO burn-rate monitor.
- Customer-facing impact is possible if the condition persists beyond 15 minutes.

## Diagnosis

1. **Check upstream dependency health**
   - Command: `atlasctl deps health svc-shipping`
   - Expected: Each dependency reports healthy or degraded
2. **Inspect the error budget burn rate**
   - Command: `atlasctl slo burn svc-shipping`
   - Expected: Burn rate as a multiple of budget
3. **Review recent log volume for new signatures**
   - Command: `atlasctl logs top-errors svc-shipping --window 30m`
   - Expected: Ranked error signatures with counts
4. **Verify connection pool utilisation**
   - Command: `atlasctl pool stats svc-shipping`
   - Expected: In-use versus maximum connections
5. **Check for correlated incidents on dependencies**
   - Command: `atlasctl incidents related svc-shipping`
   - Expected: Open incidents on services this one needs

## Mitigation

1. **Shed non-critical traffic**
   - Command: `atlasctl traffic shed svc-shipping --class low --percent 25`
   - Expected: Low-priority request volume drops
2. **Increase the connection pool ceiling**
   - Command: `atlasctl pool resize svc-shipping --max 200`
   - Expected: Pool utilisation falls below 80 percent
3. **Disable the offending feature flag**
   - Command: `atlasctl flags disable shipping-rollout`
   - Expected: Flag reports disabled for all cohorts
4. **Purge the affected cache namespace**
   - Command: `atlasctl cache purge svc-shipping --namespace hot`
   - Expected: Cache hit ratio recovers over 5 minutes
5. **Drain and restart unhealthy replicas**
   - Command: `atlasctl replicas recycle svc-shipping --unhealthy-only`
   - Expected: Unhealthy replicas replaced one at a time
6. **Fail over to the secondary region**
   - Command: `atlasctl failover svc-shipping --to westeurope`
   - Expected: Traffic served from the secondary region
7. **Scale out the service by one step**
   - Command: `atlasctl scale svc-shipping --replicas +2`
   - Expected: Replica count increases; p95 begins to fall within 3 minutes

## Rollback

1. **Revert any scaling change**
   - Command: `atlasctl scale svc-shipping --replicas baseline`
   - Expected: Replica count returns to the baseline
2. **Re-enable any disabled flag once the cause is understood**
   - Command: `atlasctl flags enable shipping-rollout`
   - Expected: Flag reports enabled

## Escalation

- Page `team-supply` via the primary rotation if not mitigated in 20 minutes.
- Escalate to the incident commander for any Sev1, or if blast radius exceeds 5.
